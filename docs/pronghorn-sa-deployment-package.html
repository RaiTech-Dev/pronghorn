01System Architecture

Pronghorn is a single-page React application. At runtime it has no backend of its own — all persistence, authentication, and AI logic lives in Supabase. Your home server's only job is to serve the compiled static JavaScript bundle.

Critical — Read This First

All VITE_* environment variables are baked into the JS bundle at build time, not read at runtime. You cannot change Supabase credentials by setting environment variables on a running container. Every time a VITE_* value changes, you must rebuild the Docker image.

Figure 1 — Full system architecture. Three deployment zones with all network flows.

How the Vite build pipeline works

The Docker image uses a two-stage build. Stage 1 uses oven/bun:1-alpine — the repo uses Bun as its package manager (bun.lockb is the authoritative lockfile; package-lock.json is not kept in sync, so npm ci will fail). bun run build compiles the React SPA with your VITE_* values baked in. Stage 2 copies only the compiled dist/ folder into a lean Nginx image. The Bun build tooling is discarded entirely.

Figure 2 — Two-stage Docker build. Bun (oven/bun:1-alpine) compiles; Nginx (~40 MB) serves. Build tools are discarded.

Dockerfile

Context — why these issues exist

This repo was built entirely on Lovable's managed cloud platform. No Dockerfile ever existed. Lovable abstracts the build environment — dependencies were never strictly pinned, the lockfile drifted, and nothing broke because Lovable resolved everything automatically. Containerizing required solving each gap manually. None are bugs in the app itself.

# ── Stage 1: Build ─────────────────────────────────────────
FROM oven/bun:1-alpine AS builder
WORKDIR /app
COPY package.json bun.lockb ./
RUN bun install
COPY . .
ARG VITE_SUPABASE_URL
ARG VITE_SUPABASE_PUBLISHABLE_KEY
ARG VITE_SUPABASE_PROJECT_ID
ARG VITE_ADMIN_KEY
ARG VITE_APP_URL
ENV VITE_SUPABASE_URL=$VITE_SUPABASE_URL
ENV VITE_SUPABASE_PUBLISHABLE_KEY=$VITE_SUPABASE_PUBLISHABLE_KEY
ENV VITE_SUPABASE_PROJECT_ID=$VITE_SUPABASE_PROJECT_ID
ENV VITE_ADMIN_KEY=$VITE_ADMIN_KEY
ENV VITE_APP_URL=$VITE_APP_URL
RUN bun run build

# ── Stage 2: Serve ─────────────────────────────────────────
FROM nginx:1.27-alpine AS runner
RUN rm /etc/nginx/conf.d/default.conf
COPY nginx.conf /etc/nginx/conf.d/pronghorn.conf
COPY --from=builder /app/dist /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]

Also required — package.json overrides

Add this block to package.json to pin Rollup to the version the codebase was built against. Without it, Bun resolves Rollup 4.60.x inside Alpine which has breaking changes that crash the build.

"overrides": {
  "rollup": "4.24.0"
}

After adding, run npx bun install locally and commit the updated bun.lockb before building the container.

Build issues encountered during first containerization

Issue 1 — Wrong package manager (node:20-alpine + npm ci)

The initial Dockerfile used node:20-alpine and npm ci --frozen-lockfile. Failed immediately — the repo uses Bun and package-lock.json is not maintained.

npm error `npm ci` can only install packages when your package.json and package-lock.json are in sync.

Fix: Switch to oven/bun:1-alpine, use bun install, use bun run build.

Issue 2 — Lockfile out of sync (--frozen-lockfile fails)

After switching to Bun, bun install --frozen-lockfile failed because bun.lockb had drifted out of sync with package.json. On Lovable's platform this never surfaced — their environment resolved dependencies independently of the lockfile.

error: lockfile had changes, but lockfile is frozen
note: try re-running without --frozen-lockfile

Fix: Remove --frozen-lockfile from the Dockerfile (RUN bun install). Long-term: run npx bun install locally and commit bun.lockb after any package.json change.

Issue 3 — Rollup version conflict crashing the build

bun run build failed with a cryptic Rollup parse error. Bun resolving dependencies fresh inside Alpine pulled Rollup 4.60.x — a newer version with breaking changes. The codebase was built against 4.24.0. Lovable's fixed build environment masked this conflict entirely.

Error at parseAsync (unknown)
at setSource (rollup/dist/es/shared/node-entry.js:15923:37)
error: script "build" exited with code 1

Fix: Add "overrides": { "rollup": "4.24.0" } to package.json, run npx bun install locally to regenerate bun.lockb, rebuild with --no-cache.

Issue 4 — PWA plugin incorrectly suspected (red herring)

The Rollup error showed [vite-plugin-pwa:build] in the stack trace, leading to removal of the PWA plugin from vite.config.ts. It was not the cause — the PWA plugin was simply the first module Rollup attempted to process. Once Rollup was pinned to 4.24.0, the PWA plugin was restored and the build succeeded with PWA fully intact. Do not remove the PWA plugin.

nginx.conf

server {
    listen 80;
    server_name _;
    root /usr/share/nginx/html;
    index index.html;

    # Serve pre-compressed .gz files (Vite produces these)
    gzip_static on;

    # Security headers
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;

    # Long cache for hashed assets
    location /assets/ {
        expires 30d;
        add_header Cache-Control "public, immutable";
    }

    # SPA fallback — critical for React Router
    location / {
        try_files $uri $uri/ /index.html;
    }

    # Never cache index.html
    location = /index.html {
        add_header Cache-Control "no-cache, no-store, must-revalidate";
        expires 0;
    }
}
Important

Do NOT add brotli_static on. The standard nginx:1.27-alpine image does not include the ngx_brotli module — it will cause Nginx to fail to start. gzip_static on is included and sufficient.

07Phase 3 — Supabase Configuration

Link CLI and push migrations

Windows note

npm install -g supabase is not supported. winget and Scoop may also fail depending on your setup. Use npx supabase for all CLI commands — it works reliably on Windows without any global install.

npx supabase login
npx supabase link --project-ref YOUR_PROJECT_REFERENCE_ID
npx supabase db push
Known Issue — cannot change return type of existing function (SQLSTATE 42P13)

The migration chain modifies get_repo_files_with_token across multiple files, changing its return type mid-sequence. PostgreSQL allows CREATE OR REPLACE only if the return type stays the same — a type change requires a DROP first. The original team's live database was never affected because it was already in the final state. A fresh db push replays every migration in order and hits the conflict.

Fix: Before running db push, open Dashboard → SQL Editor and run:

DROP FUNCTION IF EXISTS public.get_repo_files_with_token(uuid, uuid, text);
DROP FUNCTION IF EXISTS public.get_repo_files_with_token(uuid, text);
DROP FUNCTION IF EXISTS public.get_repo_files_with_token(uuid);

Drop all three signature variants — PostgreSQL overloads functions by argument types. Then re-run npx supabase db push. Already-applied migrations are skipped; only the failed one and anything after it will run.

After db push, verify in Dashboard → Table Editor that you can see: projects, requirements, canvas_nodes, canvas_edges, audit_runs, build_sessions, artifacts, profiles, organizations, share_tokens.

How the auth system works

MethodHow
Email + PasswordVia the Sign In tab on /auth

Sign up (email/password) requires a signup code. The app calls validate-signup-code first. If no SIGNUP_CODE secret is configured, any value passes. If set, the user must enter it exactly. Account creation goes through send-auth-email which uses Resend — Resend must be configured for email/password signups to work end-to-end.

Fix required before creating users via signup

The send-auth-email edge function has pronghorn.red hardcoded as the base URL for verification links. Fix it before using the signup flow.

File: supabase/functions/send-auth-email/index.ts

// Before
const baseUrl = "https://pronghorn.red";

// After
const baseUrl = Deno.env.get("APP_URL") ?? "https://pronghorn.red";

Then add APP_URL = http://YOUR_IP:8080 as an edge function secret. This is separate from VITE_APP_URL — edge functions run server-side on Supabase's infrastructure and cannot read Vite build-time vars.

Bypasses the signup form entirely — no signup code, no Resend, no email. Use this to bootstrap your first admin account.

canvas_nodes — Diagram nodes. position is {"x": 0, "y": 0} jsonb. data holds content, labels, metadata.

canvas_edges — Directed connections between nodes. Both source/target CASCADE DELETE.

canvas_layers — Named layer groups. node_ids is text[] of node IDs.

canvas_node_types — Dynamic UI config controlling what appears in the canvas toolbar. Set is_active = false to hide node types you don't use.

Group 7 — Repositories & Source Control

project_repos — Git repo config. UNIQUE on (project_id, organization, repo).

repo_files — Full file content synced from repos. UNIQUE on (repo_id, path).

repo_staging — Uncommitted agent changes before commit. operation_type: add/edit/delete/rename.

repo_commits — Commit history. repo_pats — Encrypted GitHub PATs. UNIQUE on (user_id, repo_id).

Group 8 — Agents

agent_sessions — Autonomous agent execution. mode: task/iterative_loop/continuous_improvement.

agent_blackboard — Episodic memory. entry_type: planning/progress/decision/reasoning/next_steps/reflection.

agent_session_context — Project context snapshots at session start.

agent_file_operations — Real-time file op tracking. agent_messages — Conversation history. agent_llm_logs — Raw LLM API call log with full prompts, token counts, parse success.

Group 9 — Chat

chat_sessions — Conversation groupings with both user-set title and AI-generated title/summary.

chat_messages — Individual messages. role: user/assistant/system.

Group 10 — Artifacts & Collaboration

artifacts — Reusable content blocks (code, documents, diagrams, images).

artifact_collaborations — Active editing sessions. Tracks current_content (working copy) vs base_content (original).

artifact_collaboration_history — Full version history with rollback. Stores full_content_snapshot at each version. UNIQUE on (collaboration_id, version_number).

artifact_collaboration_messages / artifact_collaboration_blackboard — Chat and agent reasoning during collaboration.

Group 11 — Audit System

audit_sessions — Multi-agent compliance audits. Supports Tesseract 3D analysis, Venn set intersection, and consensus voting.

audit_blackboard — Shared agent memory with confidence float (0.0–1.0).

audit_tesseract_cells — 3D evidence grid. z_polarity: -1.0 (fail) to 1.0 (pass). UNIQUE on (session_id, x_element_id, y_step).

audit_agent_instances — Agent instances within a session. UNIQUE on (session_id, agent_role).

audit_graph_nodes / audit_graph_edges — Knowledge graph. audit_activity_stream — Real-time event log shown live in UI.

Group 12 — Deployment & Infrastructure

project_deployments — Deployment config per environment (development/staging/production). Supports pronghorn_cloud, local, dedicated_vm. Has Render.com integration. secrets and env_vars stored as jsonb.

deployment_logs — Deployment event log. project_testing_logs — Real-time error telemetry with stack_trace, file_path, line_number, is_resolved flag.

Group 13 — Database Management

project_databases — Provisioned DB instances. Supports render_postgres and supabase providers.

project_database_connections — External connections. connection_string is encrypted. ssl_mode DEFAULT require.

project_database_sql — Saved queries. project_migrations — Schema migration history with sequence_number and statement_type.

Group 14 — Build Books

build_books — Curated collections of best practices and standards packaged for teams. is_published controls visibility.

build_book_standards / build_book_tech_stacks — Standard categories and tech stacks included in a build book.

Group 15 — Gallery & Group 16 — Activity

published_projects — Projects published to the public gallery. Tracks clone_count and view_count.

activity_logs — General project activity catch-all.

audit_runs / audit_findings / build_sessions — Legacy tables superseded by audit_sessions and agent_sessions. Retained for migration compatibility.

Customization Quick Reference

-- Make a user an admin
INSERT INTO user_roles (user_id, role) VALUES ('<auth_user_uuid>', 'admin');

-- Set up your organization
INSERT INTO organizations (name) VALUES ('Your Org Name') RETURNING id;
UPDATE profiles SET org_id = '<org_id>' WHERE user_id = '<auth_user_uuid>';

-- Change the default LLM for all new projects
ALTER TABLE projects ALTER COLUMN selected_model SET DEFAULT 'claude-sonnet-4-5';

-- Hide unused canvas node types
UPDATE canvas_node_types SET is_active = false WHERE system_name IN ('WEBHOOK', 'FIREWALL');
